## 一、产品定位与目标

**为喜欢汽车玩具、刚接触电脑的孩子，制作一个通过鼠标观察和摆弄玩具风越野车的 3D 网页。爸爸先试玩，再陪孩子一起打开车门、查看车灯和观察减震。**

首版围绕「观察一辆车 → 让部件发生变化 → 换角度再看 → 重复探索与分享」组织体验。

### 首版优先目标

1. 车的样子和细节能吸引孩子，愿意靠近看、动手点。
2. 爸爸简单示范后，孩子能独立完成至少一种互动。
3. 部件变化清楚，能引出孩子与爸爸之间的交流，或与实体玩具的比较。

创造、知识、解决问题和成长记录是长期期待。本版先验证兴趣与操作体验，后续依据孩子的主动反馈扩展。

## 三、使用者与设备范围

### 孩子

- 约 6 岁 8 个月，刚上小学一年级。
- 能认部分汉字与常见图标，缺少电脑使用经验。
- 已观察到的兴趣：越野外形、高底盘、可开合部件、减震、滑行、自己改装并向家人展示。
- 鼠标已经选定为输入设备；孩子对鼠标的实际熟练度仍需观察。

### 爸爸

- 负责首次打开和检查，陪伴孩子尝试。
- 可以示范一次操作、围绕车辆细节聊天、记录孩子的反应。
- 愿意偶尔补充玩具或场景；基本体验应能在没有持续内容维护的情况下使用。

### 首版使用范围

- 首要验证环境为爸爸电脑上的桌面浏览器，鼠标操作。
- 首版采用网页形式作为暂定实现方向，在本机启动和试用。
- 平板、手机、外网分享与安装到桌面的方式，尚未列为首版验收要求。
- 具体电脑与浏览器环境、三维性能在开始制作时检查。

## 四、车辆与画面要求

### 真正的三维展示

- 从前、侧、后方观察时，车辆应呈现一致的三维结构与空间关系。
- 视角改变后，已打开的部件、亮灯状态与车辆结构保持一致。
- 支持鼠标拖动观察，同时提供可直接点击的常用视角与「回正」，让主要体验不依赖孩子先学会拖动。
- 视角与距离应受适当限制，避免车辆轻易移出画面或难以找回。

### 玩具风越野车

- 高底盘、明显的轮胎、清楚的车身轮廓，符合玩具越野车的观感。
- 车门、引擎盖、后备箱、车灯与轮组容易辨认。
- 打开的车门后方有简化内饰；引擎盖下、后备箱内有基本可观察的结构或空间。
- 车身、轮组、可开合部件与悬挂需要能分别运动，并保持连接关系。
- 采用通用车辆造型作为暂定设计；没有要求复刻奔驰或特警装甲车的具体品牌外观。

### 场景与美术暂定设计

- 一辆主车、一个简洁展示场景，车辆占据主要视觉区域。
- 玩具质感、柔和光照与清楚的接地阴影，部件动作容易看清。
- 初始显示能同时看到车头和一侧车身的斜前方视角。
- 初始车辆静止，便于孩子观察并主动开始操作。
- 配色和场景装饰由视觉方案提供初稿；当前不需要继续收集问卷。

## 五、首版功能范围

下表是首版草案的核心范围。用户选择确定了车辆、三维展示、三组互动和鼠标；视角辅助、恢复与状态处理属于我补充的必要配套设计。

| 编号 | 功能 | 首版行为 |
| --- | --- | --- |
| R01 | 进入展示场景 | 打开网页后加载一辆玩具风越野车，显示主要互动入口 |
| R02 | 换角度观察 | 支持鼠标拖动旋转；提供点击式前、侧、后方视角，以及回到初始视角 |
| R03 | 开关车门 | 点击后开门，再点关闭；暂按至少一对车门联动控制设计 |
| R04 | 开关引擎盖 | 单独控制打开和关闭，动作围绕合理的铰链位置，打开后能看见简化机舱 |
| R05 | 开关后备箱 | 单独控制后部开合，打开后能看见储物空间；开合方向由最终车辆结构决定 |
| R06 | 开关车灯 | 一个入口切换灯光；暂按前灯与尾灯联动，亮灭状态清楚，初始关闭 |
| R07 | 观察减震 | 点击「压一压」播放车身下压、悬挂压缩、回弹和恢复的过程 |
| R08 | 恢复体验 | 「回正」只恢复视角；另提供低干扰的「重来」入口恢复车辆与视角的初始状态 |
| R09 | 清楚的反馈 | 按钮状态与车辆状态一致；加载过程有提示，出现加载问题时给出可重试入口 |

### 部件开合的具体约定

- 车门、引擎盖、后备箱分别控制，允许同时处于打开状态。
- 开合过程中能看清动作，结束位置稳定。
- 部件绕连接处运动，不能与车身脱离或明显穿过车身。
- 连续点击时，动作与最终状态保持可理解，不出现卡住或按钮与部件相反的状态。
- 首版无需逐扇控制全部车门；具体车门数量属于模型设计细节，可在视觉方案中调整。

### 灯光的具体约定

- 开灯后，车辆上的前灯和尾灯确实发生可见变化，换角度观察时状态保持一致。
- 按钮有清楚的开启状态；再次点击后关闭。
- 首版暂用稳定灯光，不加入自动警笛或闪烁警灯。
- 灯光开关与车门、引擎盖、后备箱状态相互独立。

### 减震的具体约定

- 定位为直观的机械动作演示，先展示压缩和回弹关系。
- 能看到车身相对轮组下压，悬挂随间距变化，随后回到初始高度。
- 演示中轮胎保持合理接地，不能只让整辆车上下平移。
- 打开的部件随车身正确运动，灯光状态维持。
- 一次演示结束后可再次触发。连续点击时避免动作叠加失控，具体中途重触发方式由原型验证。
- 暂不加入弹簧参数、路面模拟、速度计算或工程精度的物理分析。

## 六、适合第一次使用的界面与交互

- 一屏集中呈现主车、主要动作与视角控制，使用过程无需寻找多层菜单。
- 三组互动在视觉上清楚分组；开合组内保留车门、前盖、后箱的独立入口。
- 主按钮使用大点击区域、明显图标与短文字，例如「车门」「前盖」「后箱」「车灯」「压一压」。
- 按钮的开启、关闭、播放状态要有清楚反馈，文字与画面一致。
- 核心流程以鼠标单击完成；拖动用于更自由的观察，键盘与滚轮不作为完成核心体验的前提。
- 「回正」容易找到；「重来」在需要时可找到，但不抢占车辆和动作的注意力。
- 暂不设置分数、倒计时、失败惩罚、奖励领取或强制教学。

### 声音暂定设计

首版默认静音、无循环背景音乐。短促的车辆音效和语音提示列为可选增强；若加入，应可关闭，并根据孩子实际反应调整。家长已明确不喜欢过吵声音，孩子不喜欢重复玩具音乐；这不等于已经确定排除全部音效。

## 七、一次完整使用流程

1. 爸爸打开网页，确认车辆显示与鼠标控制正常。
2. 孩子先看到停放的越野车，爸爸示范一次开门。
3. 孩子自己开关车门，再尝试引擎盖或后备箱。
4. 点击常用视角看另一面；愿意尝试时，由爸爸演示鼠标拖动。
5. 开灯，或点击「压一压」观察变化，可以反复操作。
6. 爸爸根据孩子的兴趣聊天，拿实体车一起比较也可以。
7. 孩子自然结束；需要重新开始时点击「重来」。

**初始状态：** 车门、引擎盖、后备箱关闭，车灯关闭，悬挂处于正常高度，视角为斜前方。

**保存暂定设计：** 当前只有车辆观察与操作状态，刷新或下次打开恢复初始状态。首版不引入账号或云端进度；作品保存等需求随以后创作玩法再讨论。

## 八、范围之外的内容

### 家长已经明确不需要

大量文字、必须答题才能玩、复杂注册、排行比较、反复点击领奖、过强碰撞表现、需要持续维护内容、过吵的声音。

### 本版建议延后

完整驾驶与竞速、城市探索、道路搭建、多任务关卡、多车型收藏、复杂改装、实体玩具自动识别或重建、作品相册、在线多人、在产品中持续调用 AI。

这些方向可根据孩子的反馈重新排优先级。首版验证重点是已选定车辆的三维观察与三组互动。

以下验收场景已用于技术检查，其中 A10 的亲子试玩仍待家长和孩子实际体验。具体执行范围与结果见实现与验证记录。

| 编号 | 怎么检查 | 通过表现 |
| --- | --- | --- |
| A01 | 打开网页并从前、侧、后方观察 | 主车清楚，三维结构一致，各视角能看见对应部位 |
| A02 | 依次开关车门、引擎盖、后备箱 | 三类部件均能操作，运动连接合理，打开后有可观察内容 |

## 十、实施前的关键检查与费用

### 需要实际验证的事项

1. **车辆表现：** 选用或制作的车辆，是否有足够的玩具质感，孩子能否认出想看的部件。
2. **部件结构：** 车门、盖板、轮组与悬挂能否分别控制；开合与减震是否连贯。
3. **设备表现：** 实际电脑和浏览器能否顺畅显示三维画面并接收鼠标操作。

以上事项已在本次制作中检查：车模采用程序构建，已验证分部件动作与当前环境下的三维运行。其他设备仍需按实际使用情况补充验证。

### 费用暂定约束

- 延续前轮建议，按不新增付费服务设计首版；这是方案默认值，家长尚未提供预算金额。
- 优先考虑自行制作或合适的免费素材，先评估是否满足所需部件动作和观感。
- 本机试用不需要购买域名或服务器，当前核心体验没有在线 AI 调用需求。
- 如出现值得使用的付费资源，先说明具体收益、费用和替代方案。
- 现有开发工具的计费与网页运行成本分别看待。

### 推荐实施顺序

1. 验证主车与一个开合动作，先确保画面和可动结构成立。
2. 完成三组互动、换视角与恢复行为，检查组合操作。
3. 爸爸完整试玩，修正影响使用的问题。
4. 爸爸陪孩子试用，记录兴趣与操作表现，再决定下一版。

家长提出的 1—2 天、或 4—5 天是期望窗口；在具体车辆与视觉方案明确前，不将其写成保证交付日期。
