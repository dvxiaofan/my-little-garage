# 家庭车库：多设备与小朋友入口

日期：2026-09-29。目标版本：v0.6。
家长已确认按家庭车库方案执行，逐步验证、提交并推送。

## 产品范围

- 一个家庭共用一个服务地址，入口展示这个家庭的小朋友头像和名字。
- 点击「添加小朋友」，填写名字、选择不同颜色与车型的 SVG 汽车头像、通过四格输入设置并确认 4 位数字口令；服务端生成唯一 ID。同名允许，身份由 ID 区分，输错口令不会创建用户。旧动物头像兼容映射为小汽车显示，不批量改写已有档案。
- 点头像输入口令进入独立车库；登录会话最长 12 小时，刷新可继续，切换小朋友会退出当前会话。过期重新输入口令。
- 当前改装与最多 6 辆作品保存到服务端。换设备登录后读取同一份车库。
- 本地旧作品仅在明确确认后导入当前小朋友；展示数量，保留原浏览器数据，不静默覆盖服务端作品。容量不足整次拒绝，先整理后重试；重复导入按造型和名字去重。
- 不再承诺断网后自动跨设备保存；明确区分保存中、已保存、网络失败、其他设备更新冲突。失败保留当前页面数据可重试；冲突可下载本次备份，再重新读取服务端。
- 切换身份前等待保存成功；未保存或冲突时不直接丢弃，可先备份。多设备同时修改以版本号检查，拒绝旧版本覆盖新版本。

## 实现选择

- 保留 TypeScript + Three.js 前端，增加 Node.js 24 原生 HTTP 与 SQLite 后端，无额外在线服务。
- 开发时 Vite 同源挂载 API，仍为固定 5173；生产构建后由 Node 同时提供静态页面和 API，可用 Docker 在 NAS 运行。
- 数据在 data/garage.sqlite（不入 Git）；配置独立数据目录可备份。测试使用临时数据库，不触碰家庭数据。
- 口令采用 scrypt 加盐哈希；会话使用随机令牌、数据库仅保存令牌摘要，HttpOnly/SameSite cookie。写入检查同源；支持 HTTPS 的安全 cookie 配置。
- 口令错误按用户和来源限速，连续失败暂锁；提供仅在服务器终端运行的家长重置命令，重置撤销已有会话。
- 家庭入口不是面向公众的多租户注册平台；局域网 HTTP 适用于当前使用方式，公网应通过 HTTPS。此轮提供 NAS 部署方式，不自动操作 NAS。

## 分步交付

1. 本方案文档。
2. 用户、口令、会话、SQLite 车库、版本冲突 API；后端集成测试、启动与家长管理命令。
3. 小朋友入口、远端保存状态、切换身份、旧作品确认导入；适配现有三维功能。
4. 多设备、数据隔离、错误口令、断网重试、冲突、迁移和触屏回归；部署与使用文档、画面检查。

## 验收重点

两个独立浏览器登录同一用户可找回作品；不同用户互不读取或覆盖；匿名不能读写车库；4 位口令校验与限速有效；重启服务后数据仍在；旧版本保存返回冲突；断网不显示已保存；未确认不迁移；切换身份不带入上一位的改装和车库；原有道路、改装、动作回归通过。
