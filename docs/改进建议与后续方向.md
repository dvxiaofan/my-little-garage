# 小小车库：改进建议与后续方向

**日期：2026-09-13**  
**基于版本：v0.2 · 轻改装台**  
**状态：代码审阅后的建议清单，尚未实施，等待家长排序。**  
**依据：通读[首版需求文档](./汽车小车库-首版需求文档.md)、[轻改装需求](./汽车小车库-轻改装需求.md)、[实现与验证记录](./实现与验证记录.md)与全部源码（约 2500 行）后整理。**

本文供后续接手的人或 AI 快速了解：当前实现哪些已经做得扎实、哪些是明确的短板、下一步建议先做什么。已落定的需求以上述三份文档为准，本文只是补充，不改变既有约定。

## 一、当前做得好、后续应保持的部分

- 视角状态与车辆状态分开管理，「回正」不会关门，「重来」不会清造型，「恢复原样」不会删作品。
- 三维场景只在有变化时重绘（脏标记），静止时不占 GPU；阴影按需更新。
- 存储容错完整：无 localStorage、写入失败、损坏 JSON、未知选项都不会阻止车库打开，且明确提示「仅本次保留」。
- 可访问性：跳转链接、aria-pressed、键盘切换玩法与弹窗焦点返回、prefers-reduced-motion 下仍能完成减震。
- 测试分层清楚：Node 原生 test runner 跑状态与车模检查（含 27 种改装组合），Playwright 跑浏览器回归；没有引入多余测试框架。
- 没有外部素材、账号、付费服务，构建结果可离线运行。

后续改动请延续这些约束，尤其是「状态隔离」「存储容错」「无外部依赖」三条。

## 二、建议优先做的三件事

按对孩子体验的影响排序。

### 1. 一键试跑

**已完成（v0.3）：** 跑步机式试跑已实现，分步方案与执行记录见[一键试跑方案](./一键试跑方案.md)。可操控驾驶、跟随相机留待孩子反馈后决定。

需求文档已把「一键试跑」排在轻改装之后。当前架构可直接支持：车模已有独立悬挂与可旋转车轮，只需固定动画（车轮转动、车身沿展台绕一圈、悬挂随假想路面起伏），不需要真实物理。预计改动集中在 `src/controller.ts`（新增试跑周期）与 `src/vehicle.ts`（车轮旋转、车身位移），并复用现有减震的「播放中不叠加、重来可取消」逻辑。

### 2. 触屏验收与按钮放大

实现记录明确写「实际触屏操作尚未作为完整验收项目」，而孩子最可能用 iPad。要做的：

- 部件与视角按钮目前最小 44px，对 4-6 岁孩子建议 56px 以上。
- Playwright 增加一组 iPad 视口 + `hasTouch: true` 的回归（拖动旋转、按钮点击、弹窗）。
- 在 Safari 实测 WebGL 与 VSM 阴影表现，必要时对移动端降级阴影类型。

### 3. 作品导出与导入

6 辆作品只存在当前浏览器，清数据、换浏览器、换端口都会丢（README 已说明）。加「下载作品文件 / 打开作品文件」（一个 JSON，复用 `design-store.ts` 现有的 `version` 字段与 `normalizeDesign` 校验）成本很低，同时解决换电脑问题，比账号与云端便宜得多。

## 三、其他产品层面的小问题

- **端口变了作品就丢**。localStorage 按网页地址隔离。建议 `启动小车库.command` 固定 `--strictPort 5173`，端口被占时明确提示，而不是让 Vite 悄悄换端口导致「我的车库」看起来消失。
- **名字长度按 UTF-16 单位还是按字形计**需要确认。emoji 占 2 个单位，孩子很可能输入 emoji，12 字上限可能提前触发。
- **文字依赖偏多**。按钮都靠中文标签，孩子不认字时只能靠图标。建议点击部件按钮时小车对应部位高亮闪一下，比标签更直观。
- **声音单薄**。当前只有三个正弦波。可加喇叭、发动机启动两个音，仍保持默认静音。
- **存储升级注意**。`normalizeDesign` 对未知选项一律回默认。将来新增部件时，旧作品会被静默改写，需要在 `version` 升级时显式迁移，而不是依赖默认值。

## 四、工程层面

- **没有 lint / format 配置，也没有 CI**。建议加 ESLint（typescript-eslint）与 GitHub Actions，跑 `npm test` 与 `npm run build`。e2e 在 CI 上需要 `npx playwright install chromium`，`playwright.config.ts` 已预留 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`。
- **`package.json` 缺 `engines`**。README 要求 Node 22.18+，测试依赖 `--experimental-strip-types`，写入 `engines.node` 可让 `npm ci` 尽早报错。
- **Three.js 单 chunk 约 599KB（gzip 约 150KB）**。本地使用可接受；若后续对外发布再考虑拆分，优先级低。
- **`启动小车库.command` 放在 docs 目录不合适**，它是可执行入口不是文档。建议移回根目录或新建 `scripts/`；当前脚本已改为 `cd` 到上级目录以保证可用。
- **测试断言只用 `node:assert`**。够用，提醒后续不要为此再引入 vitest 重复一套。

## 五、来自孩子的反馈

第一次试玩后孩子提出三个问题，记录与处理见[第一次亲子试玩反馈](./亲子试玩反馈-第一次.md)。其中侧踏板与横开后门已实现；「指定真实车型复刻」已按家长提供的越7 照片完成（v0.4，见[车型复刻方案](./车型复刻-越7方案.md)）。孩子的问题都在用真车标准衡量，后续应优先补真实车辆细节而非卡通元素。

## 六、当前不建议做

自由积木拼装、真实物理驾驶、账号与云端同步。既有文档的判断正确：先拿到孩子的真实反馈再决定。现在最缺的不是功能，而是[实现与验证记录](./实现与验证记录.md)末尾要求的三条试玩记录：**最喜欢的动作、最容易卡住的操作、他自己提出的下一件事。**
